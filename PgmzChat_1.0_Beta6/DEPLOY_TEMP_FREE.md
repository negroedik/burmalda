# Временное развёртывание PgmzChat 1.0_Beta6

## Рекомендуемый вариант: Render + PostgreSQL

В репозитории уже лежит `render.yaml`: он описывает бесплатный Node.js Web Service и бесплатную PostgreSQL-базу в регионе Frankfurt, включает HTTPS, проверку `/api/health` и случайный `PGMZCHAT_ADMIN_TOKEN`. Это удобный вариант для временной проверки, но он **не является production-хостингом**.

### Развёртывание

1. Распакуй архив и загрузи содержимое папки `PgmzChat_1.0_Beta6` в новый GitHub-репозиторий. Не добавляй токены, `.env`, дампы базы или `server/data/`.
2. Открой https://dashboard.render.com/ и создай новый **Blueprint**. Подключи свой GitHub-репозиторий, в котором находится `render.yaml`, затем нажми Apply/Deploy.
3. Дождись завершения сборки. В панели сервиса скопируй его публичный HTTPS-адрес, например `https://имя-сервиса.onrender.com`. Проверка `https://имя-сервиса.onrender.com/api/health` должна вернуть JSON со `status: "ok"` и `persistence: "postgresql"`.
4. В Render открой настройки сервиса → Environment и найди `PGMZCHAT_ADMIN_TOKEN`. Раскрой значение и скопируй его. Не добавляй его в GitHub, Android-клиент, ссылку на сайт или скриншот.
5. На компьютере открой файл `admin/admin.html` двойным щелчком. Вставь адрес сервера и токен, нажми **«Проверить и загрузить устройства»**. Админка умеет показывать устройства, фильтровать список, блокировать и разблокировать код устройства и экспортировать список устройств в JSON. Токен не сохраняется в `localStorage`/cookies и очищается при закрытии вкладки.
6. В приложении PgmzChat открой настройки сервера и укажи **корневой адрес**, например `https://имя-сервиса.onrender.com` — без `/api` в конце. Для веб-клиента достаточно открыть этот же корневой адрес.

Если Render не может создать ресурсы автоматически, проверь, что в аккаунте не занята единственная бесплатная PostgreSQL-база и что Blueprint подключён к правильной ветке GitHub.

## Что сохраняется

- PostgreSQL хранит только аккаунты (`id`, username, соль и хеш пароля) и записи кодов устройств/банов.
- История, сообщения, контакты, каналы, стикеры и медиа на сервер не записываются; обмен должен происходить между подключёнными клиентами.
- Активные сессии, присутствие устройств и ожидающие WebRTC-сигналы остаются в оперативной памяти и теряются при перезапуске. Это штатное ограничение текущей альфа-архитектуры.

## Бесплатные ограничения Render — обязательно прочитай

- Бесплатный Web Service засыпает после 15 минут без входящего HTTP-трафика; пробуждение может занять около минуты.
- Бесплатный Render PostgreSQL ограничен 1 ГБ и **истекает через 30 дней**. После истечения есть 14 дней, чтобы перейти на платный план, затем данные удаляются. Резервные копии для free-базы не предоставляются.
- Бесплатный файловый диск Web Service не постоянный. Поэтому конфигурация специально использует PostgreSQL, а не JSON на локальном диске.
- Не используй этот стенд для реальных секретных переписок, больших сообществ или данных, которые нельзя потерять. Перед истечением бесплатной БД сделай экспорт/переезд и проверь восстановление.

## Запуск без Render

Можно запустить локально Node.js 20+ без `DATABASE_URL`: тогда аккаунты и коды устройств хранятся в `server/data/accounts.json` и `server/data/devices.json`.

```bash
cd server
npm install
PGMZCHAT_ADMIN_TOKEN='замени-на-длинный-случайный-секрет' node server.mjs
```

Открой `http://localhost:8080`. Не публикуй локальный HTTP-сервер прямо в интернет без HTTPS и настройки защиты.

## Пределы готовности

Это временный тестовый стенд Beta6. P2P-соединения могут не установиться у части сетей, поскольку в текущем клиенте нет настроенного TURN-сервера; фоновые доставки Android не гарантируются. WebRTC-транспорт шифрует канал, но полноценная аудированная схема сквозного управления ключами, подпись устройства и независимый аудит безопасности ещё не реализованы. Не называй этот прототип анонимным или безопасным для высокочувствительных данных.
